# アーキテクチャ — Block Drop

最終更新: 2026-09-08

## 全体構成

```
  キーボード ─┐
              ├─▶ platform/input ──▶ Action
  タッチ ─────┘   （左移動 / 右移動 / 右回転 / 左回転 /
                    ソフトドロップ / ハードドロップ / ホールド / ポーズ）
                              │
                              ▼
  ┌───────────────────────────────────────────────────┐
  │ core/    DOM に一切触らない。Node 上で単体テストできる  │
  │                                                     │
  │   types      共有の型（Cell, Piece, GameState …）     │
  │   constants  盤面サイズ・スコア式・落下速度・各種閾値    │
  │   pieces     7種の形状と 4回転状態の座標                │
  │   srs        壁蹴りテーブルと回転の成立判定             │
  │   board      固定セルの保持、衝突判定、ライン消去        │
  │   randomizer 7-bag（乱数は注入）                       │
  │   scoring    加点とレベル計算                          │
  │   game       状態機械。tick(dt) と apply(action)       │
  └───────────────────────────────────────────────────┘
                              │ GameState（読み取り専用）
                 ┌────────────┴────────────┐
                 ▼                         ▼
       platform/render ─▶ Canvas   platform/storage ─▶ localStorage
                                            （自己ベスト）
```

**依存は platform → core の一方向のみ。** `core/` から `window` / `document` / `Math.random` / `Date.now` を参照しない。乱数はシードを引数で注入し、時間は `tick(dt)` の引数で受け取る。

この分離を設計の中心に据えた理由は2つある。

1. **一番バグりやすい部分をテストできるようにするため。** 7種 × 4回転状態 × 5オフセットの壁蹴りテーブルは添字の取り違えが起きやすく、目視で検証しきれない。DOMから切り離せば `vitest` が Node 環境でそのまま走る。
2. **不具合を再現できるようにするため。** 乱数を注入式にすると、シードを固定してピースの出現順を完全に再現できる。「あの場面で回転できなかった」を後から調べられる。

違反は機械的に検出できる。`core/` 配下で `window` / `document` を参照すると、Node で走るテストが `window is not defined` で落ちる。

## 技術選定

| 領域 | 採用 | 理由 |
|---|---|---|
| 言語 | TypeScript 5 | 回転状態インデックス・座標・キックテーブルの添字ミスを型で防ぐ。このゲームで最も壊れやすい箇所に効く |
| ビルド | Vite 7 | 設定ほぼゼロで TS と開発サーバーが動き、`vite build` の出力をそのまま静的配信できる |
| テスト | Vitest | Vite と設定を共有でき、`core/` を Node 環境で実行できる |
| 描画 | Canvas 2D（ライブラリなし） | 200マスの矩形を塗るだけ。実行時依存ゼロ |
| 永続化 | localStorage | 自己ベスト1件のみ。サーバー不要 |
| 配信 | GitHub Pages + GitHub Actions | 公開リポジトリなら無料。push で自動公開される |

### 採用しなかった案

| 案 | 却下した理由 | 再検討する条件 |
|---|---|---|
| Phaser などのゲームエンジン | シーン管理・物理・スプライトを一切使わないため釣り合わない。バンドルが数百KB増える | 3Dや複雑な物理が必要になったら |
| 素の JavaScript（ビルドなし） | `push` だけで公開できる利点は大きいが、SRSの添字操作に型が効かない。今回その部分を実装すると決めたので型を優先 | ビルド工程が負担になったら |
| JS + JSDoc 型注釈 | 型検査は得られるが記法が冗長。TypeScript を避ける理由が今回ない | 同上 |
| React などのUIフレームワーク | 毎フレーム全面を描き直すゲームに仮想DOMの差分計算は不要 | 画面数が増えたら |
| DOM要素で盤面を描く | 200要素の更新は Canvas より遅く、コードも複雑になりやすい | — |
| 状態管理ライブラリ | 状態は `GameState` 1つで、更新は `core/game` の関数だけ。導入する理由がない | — |

## レイヤと責務

| ディレクトリ | 責務 | 依存してよい先 |
|---|---|---|
| `src/core/` | ゲームのルール。純粋な計算のみ | `src/core/` 内のみ |
| `src/platform/input/` | 生の入力イベントを `Action` に翻訳する | `src/core/types` |
| `src/platform/render/` | `GameState` を Canvas に描く | `src/core/types`, `src/core/constants` |
| `src/platform/storage/` | 自己ベストの読み書き | なし |
| `src/main.ts` | 配線とゲームループ | すべて |

## 横断的な決めごと

- **ゲームループ**: `requestAnimationFrame` + アキュムレータによる固定タイムステップ。フレームレートが変動しても落下速度が変わらないようにする。タブが非アクティブになった間の巨大な `dt` は上限で切り捨てる
- **座標系**: 盤面は左上原点、y は下向き。**参考資料の多くは y 上向きで書かれているため、キックテーブルは y を反転させた値で保持する**（符号ミスの最頻出箇所なので、テストで検算する）
- **盤面の高さ**: 表示は20行だが、内部は上に2行のバッファを持つ。出現直後のピースが画面外にはみ出しても扱えるようにするため
- **エラーの扱い**: `localStorage` はプライベートモードや設定によって例外を投げる。**読み書きは必ず try/catch で囲み、失敗したらメモリ上の値にフォールバックする。** ここでクラッシュすると「開いても遊べない」という最悪の結果になる
- **描画のスケール**: Canvas は `devicePixelRatio` を考慮した実解像度で確保し、CSS 側で表示サイズを決める。スマホでぼやけないようにするため
- **秘密情報**: 持たない。公開リポジトリなので、環境変数や鍵を必要とする実装は入れない

## 変更履歴

実装中に設計判断を変えたら、ここに1行残す。

| 日付 | 変えたこと | 理由 |
|---|---|---|
| 2026-09-08 | `srs.tryRotate` から `board` 引数を外し、配置可否の判定関数を注入する形にした | `srs` が `board` に依存すると Phase 2-A と 2-B が並列にならず、2-B のテストも 2-A の完成待ちになるため。副次的に、合成した判定関数だけでキックを検証できるようになった |
| 2026-09-08 | `GameState` に `seed` を追加 | 乱数を注入式にしたのは不具合を再現するためだが、実プレイのシードがどこにも残らないとその仕組みが働かない。報告されたシードから同じ局を再現できるようにした |
| 2026-09-08 | `Phase` から `'ready'` を削除 | 要件が「URLを開くと落ちてくる」なので開始待ちの状態が存在しない。使われない状態を型に残すと、扱いを考えさせるだけ無駄になる |
| 2026-09-08 | `#overlay` に `pointer-events: none` を付けた | 全画面を覆うため、ポーズ中に PAUSE ボタンを押せず再開できなかった。キーボードの無いスマホでは詰みになる |
| 2026-09-08 | `#overlay[hidden] { display: none }` を明示 | id セレクタの `display: grid` がブラウザ既定の `[hidden]{display:none}` より優先され、`element.hidden` が効いていなかった |
| 2026-09-08 | リスタート時、シードを現在の値から決定的に導出する（`deriveNextSeed`） | 同じシードで再開すると毎回まったく同じ局になり遊べない。かといって `Date.now()` を使うと core が非決定的になる。導出にすれば「最初のシード1つでセッション全体が再現できる」性質を保てる |
