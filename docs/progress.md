## 2026-09-08 — Phase 3: 状態機械 完了

**やったこと**
- `src/core/game.ts` — `tick(deltaMs)` と `apply(action)` の状態機械。自然落下・ソフト/ハードドロップ・ロック猶予・ライン消去と加点・ホールド・ポーズ・リスタート・ゲームオーバー
- `tests/game.test.ts` — 20テスト
- 現在: `pnpm typecheck` 通過、`pnpm test` **6ファイル / 104件すべて通過**

**契約の変更**（`docs/architecture.md` の変更履歴にも記載）
- `GameState` に `seed` を追加
- `Phase` から使われない `'ready'` を削除
- リスタートはシードを決定的に導出して次の局へ。最初のシード1つでセッション全体が再現できる

**実装中に自分で作り込んだ不具合と、その対処**
- **`hold` の処理を実装し忘れたまま型チェックが通った。** `switch` に網羅性チェックが無かったため。`apply` を「局を操作するもの（restart / togglePause）」と「盤上のピースを動かすもの」に分け、後者の引数型からその2つを除外して `default` で `never` 代入するようにした。以後、操作を増やしてここに書き忘れると型エラーになる

**テスト設計で分かったこと**
- 「左端に寄せて N 列右へ動かしてハードドロップ」を掃引する素朴な戦略では、**隣り合うピースが重なって塔になり、行が埋まる前に天井へ届く**（48試行中2回しか消えなかった）。運のよいシードを探すと壊れやすいテストになるため、公開APIだけを使う簡単な貪欲プレイヤー（完成行を優先し、穴と高さを嫌う評価関数）をテスト内に実装し、ライン消去とレベル上昇を確実に再現させた
- ソフトドロップの検証で、刻み幅を落下間隔より小さく取ると「まだ時間が足りなくて落ちていないだけ」を「着地した」と読み違える。ヘルパーの刻み幅は間隔より大きく取る必要がある

**既知の小さな割り切り**
- ロック猶予の加算に、その tick で落下に消費した時間も含めている。500ms の猶予に対して 1フレーム分の誤差なので、体感には影響しない

**次にやること**
- Phase 4 を**サブエージェント3並列**で実行する（4-A 描画 / 4-B キーボード入力 / 4-C タッチ入力・保存）。`GameState` が確定したので配れる
- **4-A への申し送り**: `CELL_SIZE_PX = 30` 固定では高さ570px程度のビューポートに盤面が収まらない（Phase 1 で実機確認済み）。画面サイズに合わせた縮尺は必須。NEXT / HOLD のプレビュー canvas も寸法未設定で間延びしている

**設計の検証結果**
- `core/` から `window` / `document` / `Math.random` / `Date.now` への参照なし。Node 環境でテストが走る前提は守られている
- 依存の向きは `board → pieces`、`randomizer → pieces`、`srs → types のみ`。**`srs` が `board` に依存していないことを確認**（並列化の前提）
- 関数名の重複ゼロ。3エージェントが同じユーティリティを各自で書く事態は起きなかった

**統合で見つけたこと**
- モジュール間の契約が単体テストでは守られていなかった。`srs.tryRotate` は盤外にはみ出すキック候補も `isValid` に渡すため、`board.isValidPosition` が**例外を投げずに false を返す**ことに依存している。この前提が崩れると「左壁ぎわで回転するとクラッシュする」という分かりにくい壊れ方をするので、`tests/integration.test.ts` で固定した
- 各担当の報告から拾った、後続で効く注意点:
  - `clearLines` は消去0件のとき**引数と同一参照**を返す（変化の判定に使えるが、常に新オブジェクトを期待すると外れる）
  - `lockPiece` は変更した行だけ新しい配列にし、他の行は元と共有する。`readonly` を外して書き換えると別の盤面まで壊れる
  - `O` の `tryRotate` は見た目が変わらないまま `rotation` を 0→1→2→3 と進める
  - `dropIntervalMs` は `MAX_LEVEL` ではなく `DROP_INTERVAL_MS.length` で頭打ち。両者の整合はテストで固定済み
  - **`GameState` にシードを保持するフィールドがない。** 不具合再現を実際に機能させるなら Phase 3 で追加を検討する（契約変更になるため 2-C は手を付けなかった）

**採用しなかった提案**
- なし。3件とも契約からの逸脱はなかった
